## ## 1. 노드 특수성 및 입력(Input) 예외 규칙
**목적**: 사용자의 추상적이고 비정형화된 원문(Raw Idea)을 파싱하여, 전체 소프트웨어 생명주기(SDLC)의 절대적 진실 공급원(SSOT)이 될 정형화된 메타데이터 및 에픽(Epic) 구조로 변환함.
- **Source Documents 취급 예외**: 본 노드에 한하여 주입되는 `$SOURCE_DOCUMENTS`는 선행 DAG 노드의 JSON 산출물이 아닌, **'사용자의 자연어 요구사항 원문'**으로 취급함.
- **원문 파기 원칙 (Raw-Data Destruction)**: 본 노드의 산출물 생성 직후 사용자의 원문은 파이프라인에서 영구 폐기됨.
## 2. 다단계(N-Iteration) 생성 모델
본 노드는 비정형 텍스트를 다루는 특수성을 가지므로, 주입된 `$ITERATION_COUNT` 변수에 따라 AI 에이전트의 페르소나 및 출력 제약 수준을 동적으로 전환함.
### 2.1. Phase I (초기: Iteration 1~2) - 창의적 발산 (Divergence)
- **목표**: 원문의 행간을 파악하여 누락된 잠재 요구사항(Latent Requirements)과 엣지 케이스를 선제적으로 도출함.
- **허용된 창조적 확장**: 사용자가 명시하지 않았더라도 비즈니스 도메인상 필수적인 에픽(예: 이커머스 원문에서 '결제/환불' 에픽 누락 시 자동 추가)의 확장을 적극 허용함.
- **기술 스택 탐색**: 구체적 요구가 없는 경우, 최신 트렌드와 도메인 적합성을 고려하여 아키텍트 관점에서의 과감한 기술 스택(Tech Stack) 제안을 허용함.
### 2.2. Phase II (중기: Iteration 3~4) - 구조적 수렴 (Convergence)
- **목표**: `$EVALUATOR_FEEDBACK`을 기반으로 과도하게 발산된 아이디어를 스코프(Scope) 내로 재단하고, 내부 정합성을 교정함.
- **마이크로 설계 배제**: Phase I에서 아이디어 구체화를 위해 혼입되었을 수 있는 화면 스케치, 세부 API 로직, 컬럼 레벨의 데이터 구조 등을 완전히 삭제하고 철저히 '에픽(Epic)' 단위의 추상화 계층으로 수렴시킴.
- **관계망 교정**: 역할(`target_roles`)과 에픽 간의 매핑 오류 및 무결성을 검토하여 누락/오참조를 제거함.
### 2.3. Phase III (말기: Iteration 5 이상) - 결정론적 고정 (Deterministic Fixation)
- **목표**: 오케스트레이터의 기계적 파싱을 위한 100% 무결성 확보.
- **발산 전면 금지**: 이 단계부터는 새로운 에픽이나 요구사항의 창조적 도출을 엄격히 금지함 (Zero-Hallucination 강제 적용).
- **상수 확정**: 모든 기술 스택 및 메타데이터 값을 확정된 단일 상수로 고정하며, 인수 조건(Acceptance Criteria)을 테스트 엔지니어가 즉각 실행할 수 있는 객관적 명제로 100% 치환함.
## 3. 스키마 블록별 데이터 통제 규칙
### 3.1. 메타데이터 & 비즈니스 컨텍스트
- **버전 및 상태 고정**: `version`은 "1.0.0"으로, `status`는 "DRAFT"로 고정 초기화함.
- **성공 지표(Success Metrics) 정량화**: (Phase II 이후 강제) 도출된 비즈니스 성공 지표는 반드시 측정 가능한 정량적 수치(예: "출시 후 3개월 내 MAU 10만 달성")로 치환하여 서술함.
### 3.2. 역할 및 권한 (User Roles)
- **식별자 패턴 강제**: 모든 사용자 역할은 `^ROLE-[A-Z0-9-]+$` 패턴의 `role_id`를 가져야 함.
- **권한 위계 매핑**: 스키마에 정의된 Enum 타입(`GUEST`, `USER`, `ADMIN`, `SYSTEM`) 중 가장 적합한 레벨에 1:1 매핑함.
### 3.3. 핵심 에픽 (Core Epics)
- **식별자 패턴 강제**: 생성되는 모든 에픽은 `^EPIC-[A-Z0-9-]+$` 패턴의 `epic_id`를 가져야 함.
- **내부 참조 무결성**: 에픽의 `target_roles` 배열에는 직전 '사용자 역할' 블록에서 생성한 `role_id`만이 삽입되어야 함 (고스트 식별자 참조 불가).
### 3.4. 기술 스택 자동 추론 (Tech Stack Deduction)
- **결정론적 기술 스택 고정**: `tech_stack` 객체 하위의 Enum 필드는 절대 `null`이나 "TBD"가 될 수 없음. Phase I에서의 탐색을 거쳐 Phase III에서는 가장 안정적이고 비즈니스 제약(Global Constraints)에 부합하는 단일 기술 스택으로 완벽히 고정함.
