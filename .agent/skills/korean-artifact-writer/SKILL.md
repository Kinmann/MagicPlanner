# 한국어 아티팩트 작성 가이드라인

이 스킬은 `task.md`, `implementation_plan.md`, `walkthrough.md` 등의 아티팩트를 한국어로 작성할 때 일관된 어조와 정확한 번역을 보장하기 위해 사용됩니다.

## 1. 문서별 한국어 작성 지침

### 1.1 Task (task.md)
*   체크리스트 형식 사용: `[ ]`, `[/]`, `[x]`
*   명료한 어미 사용: "~ 생성", "~ 수정", "~ 구현"
*   하위 항목이 있을 경우 들여쓰기를 활용하여 계층 구조 유지

### 1.2 Implementation Plan (implementation_plan.md)
*   **배경 및 목표**: 작업의 목적을 한국어로 명확히 요약
*   **사용자 검토 사항**: 중요한 결정 사항이나 위험 요소는 `> [!IMPORTANT]` 또는 `> [!WARNING]`을 사용하여 강조
*   **개발 제안**: 파일별 변경 사항을 `[MODIFY]`, `[NEW]`, `[DELETE]`와 함께 한글 파일 이름(링크 포함)으로 표기
*   **검증 계획**: 테스트 명령어와 수동 확인 절차를 구체적으로 한글로 기술

### 1.3 Walkthrough (walkthrough.md)
*   전체적인 완성도를 체계적으로 정리
*   수행한 작업 내용과 결과를 사용자가 이해하기 쉽게 서술
*   테스트 결과와 시각적 데이터(캡처, 기록물)를 효과적으로 배치

## 2. 문체 가이드
*   **해요체** (친절한 말투) 또는 **하십시오체** (공식적인 말투)를 상황에 맞춰 사용하되, 정보 전달이 위주인 아티팩트는 가독성을 위해 간결한 명사형 어미를 권장합니다.
*   IT 기술 용어는 억지로 번역하기보다 원문을 병기하거나 널리 쓰이는 한국어 용어를 사용합니다. (예: PR -> 풀 리퀘스트, Artifact -> 아티팩트) 필요 시 괄호를 병기합니다 (예: "엔티티(Entity)", "컴포넌트(Component)").

## 3. 기타 공통 지침
*   **ArtifactMetadata**: 아티팩트 상단의 `Summary` 필드 또한 반드시 한국어로 작성합니다.
*   전문적이고 명료한 한국어를 사용하며, 아티팩트의 표준 형식과 구조는 유지하되 모든 내용을 번역합니다.
