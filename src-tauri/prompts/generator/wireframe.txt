# Wireframe 작성 원칙

## 1. 개요 및 위상 (Overview & Status)
- **위상**: 본 문서는 DAG 파이프라인의 여섯 번째 노드임.
- **의존성**: FSD의 `FUNC-{NNN}`, `data_requirements`, User Flow의 시나리오, IA의 `SCR-{NNN}`을 핵심 입력원으로 함.
- **목적**: 논리적 기능과 데이터를 시각적 UI 컴포넌트 및 레이아웃으로 변환 정의.

## 2. Wireframe 특화 작성 통제 원칙 (Domain Principles)

### A. 이전 설계 계승 및 발전 (Refinement)
- 만약 `$PREVIOUS_DRAFT`에 데이터가 존재한다면 이를 기본 골격으로 삼으십시오.
- `$EVALUATOR_FEEDBACK`의 내용을 분석하여 결함 사항을 최우선으로 교정하고, 기존의 정합성 있는 UI 구조는 최대한 유지하십시오.

### B. 식별자 절대 동기화 및 추적성 (ID Synchronization & Traceability)
- **Screen ID (screen_id)**: IA의 `SCR-{NNN}` 식별자와 1:1 일치 필수.
- **Component ID (component_id)**: 모든 UI 컴포넌트에 `CMP-{NNN}` (예: `CMP-001`) 형태의 고유 식별자 부여 필수.
- **Element Mapping (mapped_element_id)**: 해당 컴포넌트가 IA에서 정의된 어떤 요소(`ELM-{NNN}`)에서 구체화되었는지 매핑 필수.
- **Function Mapping (mapped_func_id)**: 버튼, 폼 등 액션 요소에 FSD의 `FUNC-{NNN}` 매핑 필수.
- **No Orphan ID 정책**: 선행 산출물(IA, FSD)에 근거가 없는 화면이나 컴포넌트 생성을 금지함. 모든 UI 개체는 반드시 상위 요소(`ELM-`) 또는 기능(`FUNC-`) 식별자와 1:1 매핑되어야 하며, 매핑되지 않은 '고아(Orphan) ID'는 Critical Error로 간주됨.
- **화면 창조 금지**: IA에 없는 새로운 팝업, 모달, 페이지 등의 임의 창조 엄격 금지.

### C. UI 컴포넌트와 기능 매핑 (Component-Function Mapping)
- **인터랙션 요소**: 버튼, 폼, 링크 등 모든 액션 요소에 FSD의 `FUNC-{NNN}` 매핑 필수.
- **기능 누락 방지**: 해당 `SCR`에 할당된 모든 `FUNC`는 최소 하나 이상의 UI 컴포넌트와 연결되어야 함.

### D. 모듈 책임 경계 준수 (Module Boundary Governance)
- **책임 범위 내 UI 설계**: `[Core Responsibility]`에 정의된 본 모듈의 핵심 책임과 관련 없는 UI 블록이나 위젯을 배치하지 마십시오.
- **데이터 노출 경계**: 타 모듈 소유의 데이터나 복잡한 비즈니스 로직이 시각화되어야 하는 경우, 상세 구현 대신 '외부 데이터 영역'으로 표시하고 `[Dependencies]`에 따른 데이터 연동 접점만을 명시하십시오.

### E. 데이터 노출 무결성 (Data Exposure Integrity)
- **노출 항목 통제**: 표시되는 모든 데이터 필드는 FSD의 `data_requirements` 범위 내에서만 정의.
- **임의 데이터 금지**: FSD에 없는 더미 텍스트, 통계, 부가 정보 등의 임의 배치 금지.

### F. 기술 스택 기반 UI 컴포넌트 선정 (Tech Stack Alignment)
- 주입된 `sad_tech_stack`의 `frontend` 및 `framework` 정보를 확인하십시오.
- 해당 기술 환경(예: React + Tailwind, Tauri 등)에 적합하고 구현 가능한 표준 UI 컴포넌트를 선정하십시오.
- 글로벌 기술 스택에서 제공하는 라이브러리(UI Library)가 명시된 경우, 해당 라이브러리의 컴포넌트 명칭과 스타일 가이드를 최대한 반영하십시오.

## 3. 스키마 및 데이터 작성 규칙
- **UI 상태 명세**: User Flow 분기 및 FSD `pre_condition`에 따라 상태(Default, Disabled, Error 등) 명시.
- **원자적 컴포넌트**: 표준 UI 타입(TextInput, Dropdown, DataTable 등) 지정. 레이블링(버튼명, Placeholder 등)은 구체적 명사형 유지.

```json
{
  "screens": [
    {
      "screen_id": "SCR-001",
      "screen_name": "로그인 화면",
      "layout_regions": [

          "components": [
            {
              "component_id": "CMP-001",
              "component_type": "TextInput",

              "mapped_element_id": "ELM-001",
              "mapped_func_id": "FUNC-001",
              "mapped_data_fields": ["email"],

              "description": "사용자 인증을 위한 이메일 입력란"
            }
          ]
        }
      ]
    }
  ]
}
```
