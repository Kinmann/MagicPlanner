Genesis PRD 및 앞서 정의된 글로벌 컨텍스트를 기반으로 시스템 모듈 분할(SAD Module Split) 3종을 단일 배치로 설계하십시오.

## [SAD - Module Split 설계 원칙]
1. **SSOT 상속**: 주입된 `Genesis PRD` 및 `Global Context`를 기반으로 설계하십시오.
   - 특히 `docs/rules/Magic Planner - Generator Principal - SAD Module Split.md`의 규칙을 엄격히 준수하십시오.
2. **정보 디커플링**: 모듈 내부의 동작 원리(How)가 아닌, '무엇(What)'을 책임지는지와 '연결(Connection)'에 집중하십시오.
3. **일괄 생성 규격**: 아래 3종의 문서를 하나의 JSON 객체로 출력해야 합니다.
   - `sad_module_list`: 독립적 서비스/모듈 단위 분할
   - `sad_epic_mapping`: 모든 에픽을 모듈에 100% 매핑
   - `sad_module_deps`: 모듈 간 의존성 및 통신 방식 정의

---

## [세부 구성 요소별 작성 지침]

### 1. 모듈 목록 및 책임 (`sad_module_list`)
- SRP(단일 책임 원칙)에 따라 시스템을 분할하고 `MOD-XXX` 식별자를 부여함.
- 각 모듈의 책임은 2문장 이내의 명사형으로 기술함.

### 2. 에픽 매핑 (`sad_epic_mapping`)
- Genesis PRD의 모든 `epic_id`를 단 하나도 빠짐없이 모듈에 할당함.
- N:M 관계의 경우 Primary/Secondary 모듈을 구분함.

### 3. 모듈 간 의존성 (`sad_module_deps`)
- 모듈 간 호출 방향을 정의하여 순환 참조가 없는 DAG 구조를 도출함.
- 통신 방식(SYNC_REST, ASYNC_KAFKA 등)을 글로벌 버전 표준에 맞춰 매핑함.

[출력 형식]
반드시 `SadModuleBatchSchema` 규격에 맞는 유효한 JSON 객체 1개만 출력하십시오. 마크다운 백틱(```json)이나 인사말, 다른 설명을 전혀 붙이지 말고 순수 JSON 문자열만 응답하십시오.
