# API 평가 지표 (Domain Metrics: 70점 만점)

본 지표는 파이프라인의 Phase 3 병합 노드인 API 명세서 산출물에 배타적으로 적용되는 70점 만점의 특화 검증 기준입니다. FSD의 비즈니스 로직과 ERD의 물리 구조가 인터페이스 규약으로 완벽히 치환되었는지 검증하십시오.

### Metric D: RESTful 아키텍처 및 식별자 추적성 (RESTful & Traceability)
- **기본 점수: 20점**
- **[감점 트리거]**
    - **Code D-1 비표준 URI 및 메서드 (-10점):** URI 경로에 동사(예: `/getUsers`)가 포함됨 `OR` HTTP 메서드 사용이 목적에 어긋남(조회에 POST 사용 등).
    - **Code D-2 기능 추적성 단절 (-10점):** API 엔드포인트에 선행 FSD의 기능 식별자(`FUNC-XXX`)를 매핑하는 `mapped_func_id` 필드가 누락되거나 잘못된 형식을 사용함.

### Metric E: 데이터 스키마 및 래퍼 정합성 (Schema & Wrapper Consistency)
- **기본 점수: 20점**
- **[감점 트리거]**
    - **Code E-1 ERD 타입/필드 불일치 (-10점):** 페이로드의 필드명/타입이 ERD 스펙과 충돌함 `OR` 필수(`NOT NULL`, PK, FK) 컬럼이 누락됨.
    - **Code E-2 정규화 래퍼 위반 (-10점):** 성공/실패 응답의 최상위 구조가 지정된 규격(`status`, `message`, `data`)을 준수하지 않음.

### Metric F: 보안 및 예외 메타데이터 통제 (Security & Exception Metadata)
- **기본 점수: 15점**
- **[감점 트리거]**
    - **Code F-1 인증 헤더 명세 누락 (-10점):** 권한이 필요한 기능임에도 `headers` 파라미터에 인증 토큰(Auth) 규격이 누락됨.
    - **Code F-2 해피 패스 편향 및 오용 (-5점):** 성공 응답(2xx)만 명세되고 실패 응답(4xx)이 전무함 `OR` 상태 코드 시맨틱을 위반함.

### Metric G: 대규모 데이터 제어 기제 (Data Control Mechanism)
- **기본 점수: 15점**
- **[감점 트리거]**
    - **Code G-1 페이징 제어 부재 (-10점):** 목록 조회의 경우 `limit`, `offset`(또는 `page`) 등의 페이징 파라미터가 명세되지 않음.
    - **Code G-2 정렬 필터 기준 누락 (-5점):** 복수 데이터 조회 API임에도 정렬 파라미터(`sort_by`, `order`) 명세가 누락됨.

**[검증 가이드]**
- 감점 발생 시 해당 사유를 반드시 최종 출력의 `critical_errors` 배열에 기록하십시오.
- 각 Metric의 최종 점수는 `MAX(0, 기본 점수 - 누적 감점)`으로 산출합니다.
