## 특화 평가 지표 (Domain Metrics) : 총점 70점

**[점수 연산 원칙]**

- 각 Metric의 최종 점수 산출 공식: `MAX(0, 기본 점수 - 누적 감점)`
- 감점 발생 시 해당 사유를 반드시 최종 출력의 `critical_errors` 배열에 기록하십시오.

### Metric D: 테스트 커버리지 및 예외 시나리오 포괄성 (Coverage & Exception Scenarios)

정상 흐름(Positive) 외에 부정 흐름(Negative) 및 경계값(Boundary) 등 엣지 케이스에 대한 테스트 시나리오가 누락 없이 작성되었는지 검증합니다.

- **기본 점수:** 20점
- **[감점 트리거]**
    - **[-10점] 해피 패스 편향 (Happy Path Bias):** 특정 기능(`func_id`)에 대해 정상 입력/성공 결과만 테스트하고, 유효성 검사 실패, 인증 에러, 네트워크 오류 등 FSD/API에 명시된 예외 상황 테스트가 누락된 경우.
    - **[-10점] 경계값 검증 누락 (Missing Boundary Analysis):** 데이터 입력 기능에서 최소/최대 길이 초과, 특수 문자, Null/Empty 값 등 경계값과 예외 페이로드를 주입하는 네거티브 테스트 시나리오가 부재한 경우.

### Metric E: 선행 명세(FSD/API)와의 추적성 (Traceability to Specifications)

작성된 모든 테스트 케이스가 FSD의 `func_id` 또는 API 명세서의 엔드포인트와 1:1로 맵핑되며, 사각지대(Blind Spot)가 없는지 교차 검증합니다.

- **기본 점수:** 20점
- **[감점 트리거]**
    - **[-10점] 미검증 기능 방치 (Unverified Function):** FSD나 API 명세서에 정의된 핵심 기능 중 단 하나의 테스트 케이스도 할당되지 않은 '검증 사각지대'가 존재하는 경우.
    - **[-10점] 고아 테스트 (Orphan Test Case):** 선행 명세서(FSD, API)에 존재하지 않는 임의의 기능이나 화면을 테스트하겠다고 작성하여 추적성(Traceability)이 단절된 환각(Hallucinated) 테스트의 경우.

### Metric F: 기대 결과의 결정론적 판별성 (Deterministic Expected Results)

테스트의 '사전 조건(Pre-condition)', '수행 단계(Steps)', '기대 결과(Expected Result)'가 주관적 해석의 여지 없이 기계적으로 판별 가능하게 작성되었는지 평가합니다.

- **기본 점수:** 15점
- **[감점 트리거]**
    - **[-10점] 주관적/추상적 기대 결과 (Subjective Expected Result):** 기대 결과가 "빠르게 로딩된다", "올바르게 표시된다" 등 검증 불가능한 형용사로 기재되고, "HTTP 200 반환", "DB 레코드 1건 추가됨"과 같은 물리적/상태적 값으로 명세되지 않은 경우.
    - **[-5점/건] 검증 불가 사전 조건:** 사전 조건이 "사용자가 준비된 상태"처럼 모호하며, "유효한 JWT가 쿠키에 저장됨", "Project 테이블에 ID 1번 데이터 존재" 등 테스트 환경을 재현할 수 있는 구체적 상태로 정의되지 않은 경우.

### Metric G: E2E(End-to-End) 통합 시나리오 정합성 (E2E Integration Scenario)

단일 기능의 단위 테스트(Unit Test)를 넘어, 사용자의 실제 목적 달성을 위한 다중 단계 통합 시나리오가 논리적으로 연결되었는지 검증합니다.

- **기본 점수:** 15점
- **[감점 트리거]**
    - **[-10점] 통합 동선 누락 (Missing E2E Flow):** 개별 API나 기능 단위의 파편화된 테스트만 존재하며, 생성(Create) $\rightarrow$ 조회(Read) $\rightarrow$ 수정(Update) $\rightarrow$ 삭제(Delete)로 이어지는 연속적인 데이터 생애주기 통합 테스트 시나리오가 없는 경우.
    - **[-5점/건] 테스트 간 상태 오염 방지(Teardown) 부재:** 생성/수정 테스트 이후 데이터베이스를 초기 상태로 복구(Rollback/Teardown)하는 단계나 조건이 누락되어, 후속 테스트에 부수 효과(Side-effect)를 유발할 구조적 결함이 있는 경우.
