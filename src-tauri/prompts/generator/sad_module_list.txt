Genesis PRD와 글로벌 컨텍스트를 기반으로 시스템 모듈 분할 목록 및 각 모듈의 책임을 정의하십시오.

## [SAD - Module Split 설계 원칙]
1. **정보 디커플링 (Information Decoupling)**: 모듈 내부의 동작 원리(How)를 기술하지 마십시오. 해당 모듈이 '무엇(What)'을 책임지는지에만 집중하십시오.
2. **식별자 기반 설계**: 모듈 정의 시 시스템 고유 식별자 패턴(`^MOD-[A-Z0-9-]+$`)을 반드시 부여하십시오.
3. **SSOT 참조**: `Genesis PRD` 및 선행 확정된 `Global Context`를 절대적 기준으로 삼으십시오.
4. **이전 설계 계승(Refinement)**: `$PREVIOUS_DRAFT`에 데이터가 존재한다면 이를 기본 골격으로 삼고, `$EVALUATOR_FEEDBACK`의 교정 지시 사항을 최우선으로 반영하여 모듈 목록과 책임을 개선하십시오. 기존의 유효한 `MOD-XXX` 식별자 체계는 일관되게 유지하십시오.

---

## [모듈 목록 및 책임 정의 규칙]

1. **단일 책임 및 Bounded Context 원칙**:
   - 도메인 단위로 시스템을 거시적으로 분할하고, 각 모듈에 고유한 `MOD-XXX` 식별자를 할당하십시오.
   - **과적합 및 나노 서비스 분할 엄격 금지**: 개별 DB 테이블이나 단순 CRUD 단위로 모듈을 잘게 쪼개지 말고, Bounded Context 단위로 병합하십시오 (예: User/Post 분리가 아닌 Content 모듈로 병합).
   - **모듈 개수 통제**: 시스템 복잡도를 고려하여 전체 모듈 개수를 1~3개 내외로 제한하십시오.
   - 각 모듈의 책임(Responsibility)은 최대 2문장 이내의 명사형 문체로 제한하여 기술하십시오.

2. **정보 디커플링 (CAPSULE)**:
   - 외부와의 '연결(Connection)'에 집중하고, 내부 동작 원리(How)는 서술하지 마십시오.
   - 하위 마이크로 설계 노드가 작업 범위를 혼동하지 않도록 모듈 간의 경계를 명확히 캡슐화하십시오.
