# GPRD_Architecture_Schema

생성일: 2026년 4월 19일 오후 1:22

작성 엔진(Generator)이 생성한 GPRD Architecture Schema (Stage 1-C) 산출물에 대한 교차 검증 및 정량적 평가를 수행하십시오.

## [Domain Specific 평가 지표 - 배점 70점]

공통 평가 지표(포맷 엄격성, 추적성, 결정론적 로직 - 30점) 외에 본 노드에 배타적으로 적용되는 도메인 특화 지표입니다. 평가 시작 시 70점을 부여하고, 아래 기준에 따라 감점 연산을 수행하십시오. 상위 산출물(Epic) 통합 검증 로직이 제거되어 3개의 지표로 70점을 구성합니다.

**1. 선행 제약 조건과 기술 스택의 모순 (25점)**

- **목적:** 1-A 단계의 비즈니스 제약이 기술 아키텍처에 의해 위반되는 논리적 결함 차단.
- **[감점 트리거: 건당 -10점]** `tech_stack`에 명시된 기술이 `{{APPROVED_1A}}`의 `global_constraints` (특히 `legacy_integrations` 및 `compliance`)와 기술적으로 양립할 수 없거나 정면으로 충돌하는 경우.

**2. 역할 정규화(Role Normalization) 실패 (25점)**

- **목적:** 행위자 식별자의 시스템 표준화 규격 준수 여부 검증.
- **[감점 트리거: 건당 -10점]** `user_roles` 배열의 `role_id`가 `ROLE-XXX` 형식을 따르지 않거나, `{{APPROVED_1B}}`에 존재했던 행위자(`actors`)가 `user_roles`로 누락 없이 매핑되지 않은 경우.

**3. 아키텍처 명세의 모호성 (20점)**

- **목적:** 결정론적이지 않은 기술 스택 서술 방지.
- **[감점 트리거: 건당 -10점]** `tech_stack`의 하위 필드 값이 구체적인 기술명(예: PostgreSQL, AWS S3)이 아닌, "관계형 데이터베이스", "클라우드 스토리지", "적절한 캐시 서버"와 같이 추상적이고 모호한 명사로 서술된 경우.
