# IA 작성 원칙

## 1. 개요 및 위상 (Overview & Status)
- **위상**: 본 문서는 DAG 파이프라인의 네 번째 노드임.
- **의존성**: User Flow의 `SCR-{NNN}`, `Actor`, FSD의 `FUNC-{NNN}`을 핵심 입력원으로 함.
- **목적**: 프로덕트의 전체 화면 구조(Hierarchy)를 정의하고, 주체별 진입 경로 및 구성 요소를 구조화함.

## 2. IA 특화 작성 통제 원칙 (Domain Principles)

### A. 이전 설계 계승 및 발전 (Refinement)
- 만약 `$PREVIOUS_DRAFT`에 데이터가 존재한다면 이를 기본 골격으로 삼으십시오.
- `$EVALUATOR_FEEDBACK`의 내용을 분석하여 결함 사항을 최우선으로 교정하고, 기존의 정합성 있는 정보 구조는 최대한 유지하십시오.

### B. 스크린 식별자 동기화 (Screen ID Synchronization)
- **식별자 계승**: IA의 모든 화면에 User Flow의 `SCR-{NNN}` 1:1 매핑 필수.
- **환각 통제**: User Flow에 없는 화면의 임의 창조 금지. 다중 호출되는 화면은 참조 경로(Path)만 다중 명시.

### B. 다중 주체별 계층 분리 (Actor-based Separation)
- **진입점 분리**: 식별된 주체별(User, Admin 등) 진입 포털을 논리적으로 분리 설계.
- **접근 권한(RBAC)**: 화면 단위별 접근 주체 및 최소 권한 레벨 명시.

### C. 계층적 구조 설계 (Hierarchical Depth)
- **3단계 뎁스 구조화**:
    1. Depth 1 (L1): 최상위 메뉴/핵심 서비스 영역.
    2. Depth 2 (L2): L1 하위 개별 화면.
    3. Depth 3 (L3): 화면 내 탭, 모달, 기능 블록.
- **예외 화면 편입**: 대체 흐름(에러 화면, 인증 모달 등)도 누락 없이 IA 구조에 편입.

### D. 기능 및 데이터 매핑 (Functional Component Mapping)
- **기능 배치**: 각 화면(`SCR`)에 FSD의 `FUNC-{NNN}` 매핑하여 실행 가능한 동작 명세.
- **데이터 노출**: FSD의 `data_requirements`를 참조하여 화면별 노출 데이터 리스트업.

## 3. 스키마 및 데이터 작성 규칙
- **화면 명칭**: 동작(Verb)이 아닌 상태/대상 중심의 명사형 강제 (예: "회원가입 폼 화면").
- **논리적 경로**: 계층 적합성 증명을 위해 가상 경로(URL/Path, 예: `/admin/users`) 부여.
