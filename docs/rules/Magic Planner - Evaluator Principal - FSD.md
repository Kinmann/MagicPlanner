# FSD 평가 지표

생성일: 2026년 3월 29일 오후 1:52

**[Objective]**
본 지표는 파이프라인의 두 번째 노드인 FSD 산출물에 배타적으로 적용되는 70점 만점의 특화 검증 기준입니다. 당신은 PRD(요구사항)가 기술적 구현이 가능한 단위로 정확히 분해되었는지 검증하는 컴파일러(Compiler)처럼 행동해야 합니다. 해피 패스(Happy Path) 편향을 차단하고, 엣지 케이스 및 예외 처리의 누락을 엄격하게 적발하여 감점 연산을 수행하십시오.

## 특화 평가 지표 (Domain Metrics) : 총점 70점

**[점수 연산 원칙]**

- 각 Metric의 최종 점수 산출 공식: `MAX(0, 기본 점수 - 누적 감점)`
- 감점 발생 시 해당 사유를 반드시 최종 출력의 `critical_errors` 배열에 기록하십시오.

### Metric D: 기능 분할의 원자성 및 포괄성 (Atomicity & Exhaustiveness of Functions)

PRD의 목적을 달성하기 위한 기능들이 상호 배타적이고 전체를 포괄하는(MECE) 원자 단위(Atomic)로 분해되었는지 검증합니다.

- **기본 점수:** 20점
- **[감점 트리거]**
    - **[-10점] 하위 기능 누락 (Missing Sub-functions):** PRD의 특정 기능을 온전히 구현하기 위해 시스템적으로 동반되어야 할 CRUD(생성, 조회, 수정, 삭제) 중 일부가 누락된 경우. (예: 생성 기능은 존재하나 조회 기능이 부재한 경우)
    - **[-10점] 비대화된 기능 (Bloated Function):** 단일 `func_id` 내에 2개 이상의 독립적인 도메인 로직이나 비동기 상태 전이가 혼합되어 원자성이 파괴된 경우.
    - **[-5점/건] 기반 로직 누락 (Missing Base Logic):** 프론트엔드 유효성 검사(Validation), 권한 검증(Authorization) 등 사용자 눈에 보이지 않으나 시스템 엔지니어링 관점에서 필수적인 기저 기능이 누락된 경우.

### Metric E: 상태 전이 조건의 엄밀성 (Strictness of State Transition)

기능의 `pre_condition`과 `post_condition`이 기계적으로 검증 가능한 물리적 상태값으로 정의되었는지 평가합니다.

- **기본 점수:** 20점
- **[감점 트리거]**
    - **[-10점] 검증 불가 상태 (Unverifiable State):** 조건이 "사용자가 준비됨", "로그인 상태"와 같은 추상적 자연어로 서술되고, "Session 내 유효 JWT 존재", "DB 레코드 수 > 0" 등의 테스트 가능한 데이터/물리적 상태로 특정되지 않은 경우.
    - **[-5점/건] 부수 효과 누락 (Missing Side-effects):** 기능 실행 완료 후 파생되는 비동기적 결과(예: 캐시 무효화, 감사 로그 기록, 연관 테이블 업데이트 등)가 `post_condition`에 명시되지 않은 경우.

### Metric F: 예외 흐름 및 엣지 케이스 통제 (Exception Flow & Edge Case Control)

발생 가능한 오류 및 예외 상황(Edge Cases)에 대한 시스템의 방어 로직이 명세되었는지 검증합니다.

- **기본 점수:** 15점
- **[감점 트리거]**
    - **[-10점] 해피 패스 편향 (Happy Path Bias):** HTTP 200(성공) 수준의 정상 흐름만 존재하며, 네트워크 타임아웃, API Rate Limit(429), 입력값 검증 실패(400) 등에 대한 예외 처리 로직이 전무한 경우.
    - **[-5점/건] 복구 동선 부재 (Missing Recovery Flow):** 예외 발생 시 시스템 롤백(Rollback) 정책이나 사용자 재시도(Retry) 유도 등 이전의 안정적 상태로 복귀하기 위한 구체적인 액션 플랜이 명세되지 않은 경우.

### Metric G: 데이터 입출력 명세의 구체성 (Specificity of Data I/O)

`data_requirements`의 입출력 페이로드가 개발 가능한 수준의 구체적인 스키마 속성으로 식별되었는지 평가합니다.

- **기본 점수:** 15점
- **[감점 트리거]**
    - **[-10점] 데이터 블랙박스화 (Black-boxed Data):** 필요 데이터가 "사용자 정보", "게시물 데이터" 등 포괄적인 명사로 기재되고, 실질적인 속성 키(예: `user_id`, `email`, `created_at` 등) 단위로 분해되지 않은 경우.
    - **[-5점/건] 필수 식별자 누락 (Missing Identifiers):** 특정 데이터 개체를 조회(Read), 수정(Update), 삭제(Delete)하는 기능임에도 입력(Input) 요구사항에 해당 개체를 고유하게 지칭할 식별자(PK, UUID 등)가 포함되지 않은 경우.
