# User Flow 작성 원칙

## 1. 개요 및 위상 (Overview & Status)
- **위상**: 본 문서는 DAG 파이프라인의 세 번째 노드임.
- **의존성**: FSD의 `FUNC-{NNN}` 식별자와 `Flow/Logic` 데이터를 핵심 입력원으로 함.
- **목적**: 기능 명세를 사용자 시나리오 기반 시퀀스로 재구성하여 IA 및 Wireframe의 토대 마련.

## 2. User Flow 특화 작성 통제 원칙 (Domain Principles)

### A. 이전 설계 계승 및 발전 (Refinement)
- 만약 `$PREVIOUS_DRAFT`에 데이터가 존재한다면 이를 기본 골격으로 삼으십시오.
- `$EVALUATOR_FEEDBACK`의 내용을 분석하여 결함 사항을 최우선으로 교정하고, 기존의 정합성 있는 플로우 구조는 최대한 유지하십시오.

### B. 기능 기반 경로 설계 및 추적성 (Function-Based Path Design)
- **식별자 매핑**: 모든 액션(Action) 노드는 FSD의 `FUNC-{NNN}`과 1:1 또는 1:N 대응 및 명시 필수.

### B. 행위자(Actor) 식별 및 다중 역할 분리 (Swimlane Specification)
- 모든 `User Action` 노드에 주체(Guest, User, Admin, System) 명시 필수.
- 권한별 상호작용 발생 시 상태 전이를 독립적 스텝으로 분할.

### C. 엣지 케이스 및 대체 흐름 독립 명세 (Alternative Path Specification)
- **정상/대체 흐름 분리**: Happy Path 외에 오류, 권한 거부 등 대체 흐름을 독자적 스텝으로 명시.
- **상태 기반 분기**: FSD의 `Exception Flow`를 기반으로 이진/다중 분기 Decision 노드 설계.

### D. 흐름의 무결성 및 액션-반응의 필연성
- **시스템 반응 강제**: 모든 사용자 액션은 상태 변화, 화면 이동, 에러 메시지 등 `system_response`를 반드시 동반.
- **상태 동기화**: `system_response`는 FSD의 `post_condition`과 논리적으로 일치해야 함.

### E. 화면 단위의 식별 (Screen Discovery)
- 각 단계에서 노출되는 인터페이스에 `SCR-{NNN}` 형태의 예비 식별자 할당.

## 3. 스키마 및 데이터 작성 규칙
- **진입/이탈/순환**: Entry Point와 Success State 명확화. 예외 시 재시도 루프(Retry Loop)를 설계하여 데드락 방지.
- **원자적 스텝**: 단일 책임 원칙 준수. 명사형 종결 문체 유지.
